# Admin integration placeholders

Search the backend source for `PLACEHOLDER INPUT` and `PLACEHOLDER OUTPUT`. Each marker names its entry below.

Java locations start at `backend/src/main/java/com/lms/backend/`. Interface declarations and the code that uses them are listed together. The stand-in services run in both normal mode and test mode until the corresponding owner connects the real implementation.

| ID | Other owner | File and function | What to connect and current behavior |
| --- | --- | --- | --- |
| PI-01 | Warehouse | `admin/placeholder/AdminShortageInputPlaceholder.java` → `adminReceiveShortageReportPlaceholder`. `admin/shortage/AdminShortageService.java` → `adminReadShortageCasePage`. | After verifying a shortage, call the input function with the order, product, missing quantity, note and reporting worker. It saves one `OPEN` case and returns its ID. The Stage 6 shortage-report test tool calls it now. |
| PI-02 | Warehouse | `admin/placeholder/AdminShortageInputPlaceholder.java` → `adminReceiveShortageResolvedPlaceholder`. | After restock and repacking, call the input function with the case ID and the resolving worker. It sets the waiting case to `RESOLVED`. The Stage 6 resolution test tool calls it now. |
| PI-03 | Client | `admin/delivery/AdminDeliveryCaseService.java` → `adminSearchFailedDeliveryCase`, `adminReadFailedDeliveryCases`, `adminLockInstructionOrder`, `adminRecordClientInstruction`, `adminSendDeliveryReminder`, `adminApproveRedelivery`, `adminApproveCancellation`, `adminRejectClientInstruction`. `admin/shortage/AdminShortageService.java` → `adminCloseShortageCases`. | The Client tracking page writes `ClientInstruction` rows with a `REDELIVER` or `CANCEL` type, `PENDING` status, `TRACKING_PAGE` source, delivery detail ID and current confirmed return event ID. Lock the order first before reading or writing requests. Replace the older pending row with `WITHDRAWN` so only one remains pending. Prevent delivery-detail edits after approval of redelivery. The failed-delivery fixture tool writes the tracking-page rows now. The Admin manual request action writes its own rows. |
| PI-04 | Warehouse | `admin/delivery/AdminDeliveryCaseService.java` → `adminReadFailedDeliveryCases`, `adminFindReturnState`. | On confirmed receipt, Warehouse saves a `RETURN_RECEIVED` custody event and sets the package's custody status to `WAREHOUSE`. Admin reads the latest confirmed return at or after the latest failure. The return fixture creates these rows now. |
| PI-05 | Client, Warehouse, Delivery and Payment | `shared/value/SharedPlaceholderWord.java` → `SharedPlaceholderWord`. `admin/order/AdminOrderService.java` → `adminViewOrder`, `adminReadOrderPage`. `admin/order/AdminOrderTimelineBuilder.java` → `adminAddOrderTimelineDelivery`. `admin/picking/AdminPickingService.java` → `adminReadPickingTaskPage`. `admin/user/AdminUserService.java` → `adminReadUserImpact`. `admin/temporarytest/AdminTemporaryTestToolService.java` → `adminTemporaryCreateRefundCase`, `adminTemporaryCreateSampleOrder`, `adminTemporaryCreateFailedDeliveryCase`, `adminTemporaryCreateSampleOrderRefund`, `adminTemporaryCreateSampleDeliveryAttempt`, `adminTemporaryCreateSampleRedelivery`, `adminTemporaryConfirmSampleReturn`. | Agree on the status and type words used for orders, payments, refunds, warehouse work, delivery and reservations. Change the provisional values in `SharedPlaceholderWord` together. Test tools write the provisional values now and the Admin reads use them. |
| PI-06 | Warehouse | `admin/placeholder/AdminUnavailableStockPlaceholder.java` and `admin/placeholder/AdminUnavailableStockTemporary.java` → `adminReadUnavailableStockPlaceholder`. `admin/product/AdminProductService.java` → `adminSearchProduct`, `adminReadLowStockProducts`, `adminReadProductRow`. `admin/dashboard/AdminDashboardService.java` → `adminViewDashboard`. | Return the count of damaged or held units that cannot be sold. The stand-in returns zero. Products and Dashboard use the same available-stock calculation for the low-stock filter and count. |
| PI-07 | Payment | `admin/placeholder/AdminRefundPlaceholder.java` and `admin/placeholder/AdminRefundTemporary.java` → `adminCheckRefundProviderStatusPlaceholder`. `admin/refund/AdminRefundService.java` → `adminCheckRefundStatus`. | Look up the real outcome for the refund and return `REFUNDED`, `FAILED`, `PENDING` or `UNKNOWN` with a short message. The stand-in gives `UNKNOWN` and “No payment provider is connected yet.” The test tool can override the answer for a fixture. |
| PI-08 | Client, Warehouse, Delivery and Payment | `admin/order/AdminOrderService.java` → `adminViewOrder`, `adminReadOrderPage`. `admin/user/AdminUserService.java` → `adminReadUserImpact`. `admin/log/AdminLogService.java` → `adminSearchPickingScanHistory`. `admin/picking/AdminPickingService.java` → `adminReadPickingTaskPage`, `adminViewWarehouseWorkerWorkload`. `admin/delivery/AdminDeliveryCaseService.java` → `adminReadFailedDeliveryCases`. `admin/delivery/AdminHeldPackageService.java` → `adminReadHeldPackageQuery`. `admin/refund/AdminRefundService.java` → `adminReadRefundPage`. `admin/dashboard/AdminDashboardService.java` → `adminViewDashboard`, `adminViewMenuCounter`. | The other parts save orders, order items, delivery details, payments, refunds, picking tasks, assignments, scans, packages, pickup lists, custody events, attempts and proofs in the shared tables. Local synthetic fixtures supply those rows until the owners connect their modules. |
| PO-01 | Client and Warehouse | `admin/placeholder/AdminOrderCancellationPlaceholder.java` and `admin/placeholder/AdminOrderCancellationTemporary.java` → `adminCancelOrderPlaceholder`. `admin/shortage/AdminShortageService.java` → `adminDecideShortageCancel`. `admin/delivery/AdminDeliveryCaseService.java` → `adminApproveCancellation`. | Replace the stand-in with the shared order cancellation operation so the same transaction cancels the order, releases its held reservations and ends its picking task. The local implementation performs those changes itself. |
| PO-02 | Payment | `admin/placeholder/AdminRefundPlaceholder.java` and `admin/placeholder/AdminRefundTemporary.java` → `adminRequestFullRefundPlaceholder`. `admin/shortage/AdminShortageService.java` → `adminDecideShortageCancel`. `admin/delivery/AdminDeliveryCaseService.java` → `adminApproveCancellation`. | Request the real full refund and save its row and provider result. Admin uses the newest positive accepted payment, ordered by acceptance time and then payment ID. A zero-value payment needs no refund. The Payment owner settles any other accepted payments. For an existing blocking refund, Admin reuses that refund's ID. The stand-in records a new `REQUESTED` row when needed, with no money movement. |
| PO-03 | Payment | `admin/placeholder/AdminRefundPlaceholder.java` and `admin/placeholder/AdminRefundTemporary.java` → `adminRetryRefundPlaceholder`. `admin/refund/AdminRefundService.java` → `adminRetryRefund`. | Submit a real retry and record its outcome after Admin has confirmed the most recent unresolved attempt failed. The stand-in currently adds a `REQUESTED` attempt for the same payment. |
| PO-04 | Warehouse | `admin/picking/AdminPickingService.java` → `adminSavePickingReassignment`. `admin/shortage/AdminShortageService.java` → `adminDecideShortageWait`. | Follow the open `PickingAssignmentHistory` row when authorizing scans or packing and preserve saved progress when the worker changes. Block packing while an `OPEN` shortage exists. After `WAITING_RESTOCK`, repair or replace the item and confirm packing again when the case is resolved. Admin writes the assignment and case changes now. The Warehouse workflow still needs to read them. |
| PO-05 | Delivery and Warehouse | `admin/delivery/AdminHeldPackageService.java` → `adminSaveDeliveryReassignment`. | Read the `DeliveryAssignmentHistory` change. Prevent the previous worker from starting delivery for that package, show the return task, confirm the warehouse receipt, then let the new worker collect it from a new pickup list. Admin records reassignment. The package only moves when staff physically transfer it and record custody. |
| PO-06 | Warehouse, Delivery and Client | `admin/delivery/AdminDeliveryCaseService.java` → `adminApproveRedelivery`. | Read the `READY_FOR_REDELIVERY` order and the `APPROVED` instruction. Warehouse schedules pickup again, Delivery uses the delivery detail version on the approved request, and Client locks that version. Admin saves the two states now. Role pages still need to consume them. |
| PO-07 | Client, Warehouse and Delivery | `shared/login/SharedSessionCheckFilter.java` → `sharedCheckSession`. | Put role pages and APIs under the shared access guards. Shared login already checks the account's session version, status and role on protected requests, so invalidation from Admin applies throughout this application. |
| PO-08 | Client, Warehouse and Delivery | `shared/notification/SharedNotificationSender.java` → `sharedSendNotification`. `admin/shortage/AdminShortageService.java` → `adminRecordShortageCancellation`. `admin/picking/AdminPickingService.java` → `adminRecordPickingReassignment`. `admin/delivery/AdminDeliveryCaseService.java` → `adminNotifyDeliveryClient`. `admin/delivery/AdminHeldPackageService.java` → `adminRecordDeliveryReassignment`. | Show notifications for the signed-in recipient and allow them to be marked read. Admin writes the rows now. The recipient pages still need to display them. |
| PO-09 | Client and Warehouse | `admin/product/AdminProductService.java` → `adminSaveNewProduct`, `adminEditProduct`, `adminActivateProduct`, `adminDeactivateProduct`. `admin/product/AdminProductImportService.java` → `adminSaveProductCSVLine`. `admin/product/AdminProductQRCodeService.java` → `adminViewProductQRCode`. | Client should list only `ACTIVE` products. Warehouse should use each product's inventory row and compare scanned QR text with the exact SKU. Admin maintains the catalogue and creates the stock row for each new product. |
| PO-10 | Client, Warehouse and Delivery | `shared/login/SharedStartPageRule.java` → `sharedFindStartPage`. | Add one entry for each role's start page. The shared login and session response use this mapping. Non-Admin roles now see the shared welcome page. |

The Database owner reviews the seven Admin schema changes with the team. The other development owners share the login guards, logging functions, notification writer and provisional status words. ## Warehouse consumer references

- PO-08 is read by warehouse/WarehouseOrderService.java in the signed-in worker notification inbox.
- PO-09 is consumed by warehouse/WarehousePickingService.java when it matches an order item to its saved Product SKU.
